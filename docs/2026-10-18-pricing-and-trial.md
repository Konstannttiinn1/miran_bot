## Исправление теста

Раньше `plan:test` не проверял историю заказов и при каждом нажатии повторно
вызывал выдачу VPN. Проверка наличия заказа лишь скрывала кнопку в новом меню.
Кроме того, несколько тестовых заказов вызывали `MultipleResultsFound`.
Оба дефекта воспроизведены тестами на исходном коде.

Теперь резерв теста и его заказ сохраняются одной транзакцией до обращения
к панели. Уникальный Telegram ID в `trial_claims` допускает ровно один резерв,
в том числе при одновременных запросах и из разных процессов. Проверка стоит
в сервисе выдачи, поэтому действует и при прямом вызове `grant_vpn(..., "test")`.
Активную платную подписку нельзя заменить бесплатным тестом.

Тест остаётся 1 день / 1 ГБ. Удаление подписки, окончание её срока,
перезапуск бота и удаление с повторным созданием пользователя не сбрасывают
использование теста. Дилерские тестовые ссылки с отдельным дневным лимитом
сохраняют свой действующий сценарий.

При ошибке или потерянном ответе панели резерв остаётся занятым:
панель могла успеть выдать VPN. Пользователь получает сообщение обратиться
в поддержку. Перед ручным восстановлением нужно сверить заказ, подписку и
клиента в панели; автоматически повторно выдавать тест нельзя.

## Обновление сервера

На старте `init_db()` автоматически создаёт `trial_claims` и переносит в неё
историю всех существующих тестовых заказов, включая старые дубли и ошибки.
Повторный запуск переноса безопасен. Старые заказы и подписки не удаляются.
Отдельной команды миграции не требуется.

Перед установкой проверить реальный путь службы, локальные изменения и
сохранить резервную копию кода и БД. Для известной git-установки диагностика:

```bash
cd /root/miran_bot || exit 1
git status --short --branch
systemctl show miran-bot -p WorkingDirectory -p ExecStart --no-pager
```

Если служба использует этот каталог, рабочая ветка `feat/dealer-tools-promos`
не содержит изменённых отслеживаемых файлов и резервная
копия готова, обновить код с остановкой бота, выполнить `git pull --ff-only`,
проверить компиляцию `venv/bin/python -m compileall -q app main.py`, запустить
`miran-bot` и проверить его журнал. При расхождениях путей или локальных
изменениях сначала согласовать перенос, без сброса файлов.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q tests
python -m pytest -q tests --postgres  # запуск от обычного пользователя, не root
```

PostgreSQL для второго запуска поднимается во временном каталоге и останавливается
после тестов. Тесты используют фиктивный Telegram token и подменяют вызовы панели;
рабочий бот не запускается, подключения к production-сервисам не выполняются.

Локальный результат: 32 проверки на SQLite пройдены, включая выбор обоих
VPN-провайдеров, промокоды после теста, дневной лимит дилерских тестов,
сохранность промокодов при переносе истории и импорт всех роутеров.
Компиляция Python и
`git diff --check` без ошибок. Прогон PostgreSQL в текущей среде не выполнен:
она работает от root и не позволяет запуск от другого системного пользователя.
Команда `--postgres` предназначена для обычного пользователя.
